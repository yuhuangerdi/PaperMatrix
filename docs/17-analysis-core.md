# 跨论文分析核心设计

## 1. 目标

阶段 4 是 PaperMatrix 的产品核心。它不是把多篇摘要并排展示，而是帮助用户完成以下闭环：

```text
单篇事实与证据
  → 保持完整 Markdown 并形成稳定条目
  → 选择可复现的论文范围
  → 把论文研究问题归一为领域问题
  → 分别记录各论文的方法和解决程度
  → 按方法、挑战和实验口径比较
  → 建立有证据的论文关系
  → 形成共识、冲突和未决主张
  → 把重复局限转化为研究空白
  → 生成可继续编辑的综合分析
```

所有分析都必须能回答三个问题：

1. 当前结论分析了哪些论文？
2. 结论依据了哪些页码、图、表或单篇结构化条目？
3. 哪些内容是论文事实，哪些是用户的跨论文判断？

## 2. 核心原则

### 2.1 证据优先

方法、挑战、实验结果、局限和关系不能只保存一句结论。适合进入矩阵或图谱的单篇条目应有稳定 `item_id`，并尽量附带统一的 `evidence_refs`：

- `paper_id`
- `page_label`：论文印刷页码或用户看到的页码，允许 `S3`、`iv` 等字符串
- `pdf_page_index`：可选，从 1 开始的 PDF 物理页序号
- `section`
- `figure`
- `table`
- `locator_note`：短说明，不复制大段原文
- `source_item_id`：可选，指向论文 YAML 中的方法、实验、发现或局限条目

没有证据的内容允许保存，但必须显示“待补证据”，不能与有证据结论呈现为同等可靠。

### 2.2 明确分析范围

每次跨论文分析都基于一个“分析集合”（analysis scope），而不是隐式使用项目中所有论文。集合保存名称、用途、明确的 `paper_ids`、来源筛选快照和更新时间。

- 用户可从搜索、筛选、分组或勾选结果创建集合；
- 保存时固定当时解析出的论文 ID，保证分析可复现；
- 论文记录缺失时保留 ID 并标记缺失，不静默移除；
- 同一论文可以进入多个集合；
- 矩阵、关系视图、主张和综合分析都显示当前集合。

项目总览默认提供与 Excel 文献总表等价的完整软件内矩阵，覆盖项目全部论文。分析集合是该矩阵的可复现范围视图，不取代项目总矩阵；用户可以从总矩阵筛选或勾选论文建立集合，再在同一工作界面切换范围。

### 2.3 区分事实、分类和判断

- **单篇事实**：写回 `papers/<paper-id>.yaml`，例如方法组件、实验环境、结果和局限。
- **长篇解释**：写入 `notes/<paper-id>.md`。
- **项目分类**：方法分类体系、分类定义和论文归类，写入项目级分析文件。
- **跨篇判断**：关系、共识、冲突、研究空白和综合结论，写入项目级分析文件。
- **矩阵和图形**：由上述权威文件生成，不成为第二份权威数据。

在矩阵中编辑某篇论文的事实时，必须写回该论文 YAML；编辑关系或研究空白时，必须写回对应项目级文件。

### 2.4 Markdown 解析只生成候选

结构化笔记解析器读取模板的编号标题、列表和表格，输出包含候选类型、内容、来源标题和文本位置的临时候选。候选不是权威数据：

- 解析过程只读笔记，不改写 Markdown；
- 解析失败不写论文 YAML；
- 用户在差异审阅界面逐条确认、修改或忽略；
- 只有确认后的候选才获得稳定 `item_id` 并写入 `structured_summary.items`；
- 重新解析按来源指纹和内容做重复提示，不覆盖人工编辑条目；
- 无法确定类型或证据时保留“待确认/待补证据”，不擅自推断。

### 2.5 完整笔记与条目身份并存

`notes/<paper-id>.md` 必须继续保留当前第 0–12 节模板的完整、连续 Markdown，不把条目拆为独立文件。经确认的研究问题、方法、挑战、实验、发现和局限等条目具有稳定 `item_id`、模板章节、顺序、来源锚点和来源笔记 revision；论文 YAML 只保存适合检索和分析的结构化投影。

完整文档模式和条目模式编辑同一份 Markdown。外部编辑造成条目新增、拆分、合并或边界变化时先生成差异候选，不能用旧投影覆盖新正文。个人自由内容独立保存在 `notes/<paper-id>.supplement.md`。

### 2.6 区分阅读问题、论文研究问题和领域问题

- **阅读问题**：用户阅读某篇论文时提出、待回答或已回答的问题，保存在 `questions/<paper-id>.yaml`；
- **论文研究问题**：论文自身提出、形式化或试图解决的问题，是结构化笔记中的 `research_problem` 条目；
- **领域问题**：用户综合多篇论文后确认的统一问题定义，保存在 `analyses/problem-syntheses.yaml`。

三者不能因都叫“问题”而混用。阅读问题只有先被用户整理为正式研究问题条目后，才能进入跨论文归纳。

## 3. 分析对象

### 3.1 单篇可分析条目

阶段 3 应为阶段 4 准备以下带稳定 ID 的结构化条目：

- 研究问题与适用场景；
- 方法路线、方法组件和关键机制；
- 所解决的挑战；
- 创新与附加贡献；
- 实验研究问题、环境、数据集、基线、指标、结果和复现信息；
- 作者结论与关键发现；
- 作者承认的局限、用户发现的局限和结论成立条件；
- 写作用途与证据引用。

Markdown 笔记仍可自由书写；只有需要检索、比较、关联或可视化的摘要进入 YAML。

### 3.2 项目级分析对象

- **AnalysisScope**：一次分析使用的论文集合；
- **ItemLink**：同篇或跨篇结构化条目之间的有向语义关系；
- **ProblemBoard**：绑定分析集合的一个问题归纳表；
- **FieldProblem**：用户归一化定义的领域问题；
- **PaperContribution**：某篇论文针对领域问题的方法、解决程度和证据；
- **Taxonomy**：项目内的方法或问题分类体系；
- **Classification**：论文到分类的归属及证据；
- **Relation**：两篇论文之间的有向、带类型关系；
- **Claim**：跨论文共识、冲突或仍待验证的判断；
- **ResearchGap**：由多篇证据支持的研究空白与候选研究问题；
- **Synthesis**：面向某个分析集合的可编辑综合分析 Markdown。

## 4. 核心工作流

### 4.1 建立分析集合

1. 在论文矩阵中筛选或勾选论文；
2. 点击“新建分析集合”；
3. 填写名称和分析目的，例如“自动化渗透测试中的失败恢复”；
4. 系统显示论文数量、缺失 PDF 数量和分析字段完整度；
5. 保存明确的论文 ID 列表。

分析准备度只用于提示缺失内容，不能伪装成论文质量评分。建议展示：

- 已有核心方法摘要的论文比例；
- 已有实验口径的论文比例；
- 已有局限与证据的论文比例；
- 待回答问题数量；
- 无法访问源 PDF 的论文数量。

### 4.2 领域问题归纳

用户可以在同一项目中建立多个绑定分析集合的问题归纳板。每个归纳板包含多个领域问题；一个领域问题可以映射多篇论文中经确认的 `research_problem` 条目。相似标题只能产生候选提示，问题的合并、拆分、定义和范围必须由用户确认。

每一个“领域问题 × 论文”保存一条论文贡献记录，分别关联：

- 论文对问题的表述；
- 方法、组件或机制条目；
- 实验、发现和证据；
- 解决程度及判断理由；
- 反证、失败案例和成立条件。

问题归纳表以领域问题为行，每篇论文固定提供“方法”和“解决程度”两个独立子列。解决程度为：

- `resolved`
- `partially_resolved`
- `indirectly_mitigated`
- `not_resolved`
- `not_addressed`
- `not_applicable`
- `unknown`

方法存在不代表问题已解决。系统不得从关键词、条目数量或方法存在自动生成解决程度。

### 4.3 方法与挑战比较

方法分类由用户维护定义，系统不根据关键词擅自归类。一个分类至少包含名称、定义、纳入条件、排除条件和可选父分类。

挑战—方案矩阵以“论文 × 挑战/能力”为主要方向，单元格状态为：

- `addressed`：论文明确处理；
- `partial`：只处理部分；
- `not_addressed`：明确未处理；
- `not_applicable`：不适用；
- `unknown`：尚未整理。

每个非 `unknown` 单元格都可以展开查看方法摘要和证据。热力图只是状态的视觉编码，必须同时提供文本和表格。

### 4.4 实验比较与可比性

实验比较不能只并排成功率。每个比较组先确定口径：

- 任务和成功定义；
- 数据集或环境；
- 样本/任务规模；
- 模型及版本；
- 工具权限；
- 人工参与程度；
- 运行次数与随机性；
- 指标定义和单位。

系统对任意比较组给出：

- `comparable`：关键口径一致，可直接比较；
- `partially_comparable`：部分一致，只能谨慎比较；
- `not_comparable`：关键口径不同，不给出高低排名；
- `unknown`：信息不足。

判定必须列出原因。PaperMatrix 不自动换算不兼容指标，也不把“未知”当作零。

### 4.5 关系与可视化

关系图用于回答“论文如何相互影响”，不是用于堆放全文摘要。MVP 使用固定关系类型，并为每条边保存描述和证据。

关系工作区提供两种互补视图：

1. **论文关系图**：论文为节点，显式关系为边；支持筛选关系类型、时间、分组和分析集合。
2. **邻接表**：与图完全等价的可访问表格；支持键盘操作、排序和逐条编辑。

图交互：

- 点击节点：右侧检查器显示论文摘要、关系和证据；
- 点击边：显示关系类型、方向、说明、证据和编辑入口；
- 多选节点：创建比较集合或只查看子图；
- 搜索后聚焦节点，但不删除其他数据；
- 支持自动布局和用户固定节点位置；
- 图中筛选只改变视图，不删除关系；
- 孤立论文、缺失论文和无证据关系有明确状态。

实现时使用成熟图库，Vue 技术栈优先评估 Cytoscape.js。不得手写力导向布局。移动端默认使用邻接表和节点详情，关系图作为可选视图。

### 4.6 共识、冲突与主张

图上的“结论冲突”边不足以表达复杂学术判断，因此项目需要独立的 Claim：

- `statement`：可引用的完整判断；
- `kind`：consensus、dispute、hypothesis；
- `scope_note`：结论适用范围；
- `supporting_evidence`；
- `contradicting_evidence`；
- `assessment`：用户解释；
- `confidence`：low、medium、high；
- `status`：draft、reviewed、superseded。

共识至少需要两篇独立论文的支持证据；否则 UI 使用“单篇发现”，不能显示为“领域共识”。冲突必须把条件差异与真正结论矛盾区分开。

### 4.7 从局限推导研究空白

研究空白采用可审计链路：

```text
单篇局限/失败证据
  → 多篇重复模式
  → 现有方法为何仍未解决
  → 反例或已有缓解方案
  → 可检验的研究问题
  → 候选方案
  → 验证计划与失败标准
```

一个研究空白至少关联两篇论文，或明确标记为“单篇线索”。除支持证据外，还应记录反例、适用范围、可行性和风险。删除论文记录时保留研究空白本身，但把对应引用标记为缺失，交由用户确认清理。

### 4.8 综合分析

综合分析针对一个分析集合生成 Markdown 初稿，内容只来自已确认数据：

- 范围和纳入论文；
- 领域问题、各论文方法、解决程度及其理由；
- 方法分类；
- 挑战—方案矩阵摘要；
- 实验可比性与结果；
- 共识、争议和证据强度；
- 共同局限；
- 研究空白与候选问题；
- 可用于引言、相关工作、方法、实验和讨论的素材。

生成过程不得创造缺失结论。缺少信息时写“待补充”，并提供回到源论文条目的入口。用户编辑后的综合分析是项目级权威 Markdown，重新生成时默认创建预览或新版本，不能静默覆盖。

## 5. 可视化组合

跨论文分析不应只有一张网络图。阶段 4 使用以下视图：

| 分析问题 | 首选视图 | 辅助视图 | 是否可编辑 |
|---|---|---|---|
| 不同论文如何处理同一领域问题 | 方法/解决程度双列矩阵 | 按问题展开列表 | 贡献可编辑 |
| 哪些论文互相改进、对比或冲突 | 关系网络图 | 邻接表 | 关系可编辑 |
| 哪些方法处理了哪些挑战 | 状态热力矩阵 | 分组表 | 单篇条目可编辑 |
| 实验结果是否能比较 | 可比性矩阵 | 并排明细表 | 比较组可编辑 |
| 某个结论有哪些支持与反证 | 主张—证据图 | 证据列表 | 主张可编辑 |
| 研究空白如何形成 | 证据链/漏斗 | 研究空白表 | 空白可编辑 |
| 方法如何随时间演进 | 分类时间线 | 年份表 | 分类可编辑 |

视觉编码不得只依赖颜色。网络图需要固定图例，节点类型同时用形状或图标区分；热力矩阵同时显示文字或符号；所有图都提供等价表格。

## 6. 目标文件布局

阶段 4 实现后，项目级权威分析文件统一位于 `analyses/`：

```text
<project-id>/
├── papers/
├── notes/
│   ├── <paper-id>.md
│   └── <paper-id>.supplement.md
├── questions/
├── analyses/
│   ├── scopes.yaml
│   ├── item-links.yaml
│   ├── problem-syntheses.yaml
│   ├── taxonomies.yaml
│   ├── relations.yaml
│   ├── claims.yaml
│   ├── research-gaps.yaml
│   ├── views.yaml
│   └── syntheses/
│       └── <scope-id>.md
├── artifacts/
│   └── matrices/          # 可重新生成的内部派生文件
└── exports/               # 用户主动导出的快照
```

项目级 YAML 分文件加锁、检查 revision 并原子替换。矩阵与图数据由权威文件按请求组装；不把浏览器缓存或图布局引擎内部状态当作业务数据。

## 7. 阶段拆分

### 4A：分析准备与范围

- 单篇结构化条目具备稳定 ID 和证据引用；
- 从结构化 Markdown 生成只读候选，并经差异审阅后确认写入；
- 保持当前完整 Markdown 模板并增加稳定章节、顺序、来源锚点和来源 revision；
- 提供完整文档/条目双模式、个人补充笔记、条目关系、反向引用和稳定跳转；
- 建立、修改和删除分析集合；
- 显示分析准备度与缺失项；
- 文献总矩阵按集合工作。

### 4B：方法、挑战与实验比较

- 多个问题归纳板、领域问题和论文研究问题映射；
- 每篇论文“方法/解决程度”双列矩阵及等价列表；
- 论文贡献记录关联问题、方法、实验、证据、反证和条件；
- 方法分类体系与论文归类；
- 挑战—方案矩阵和热力视图；
- 实验比较组、可比性判定和警告；
- 所有上下文编辑写回正确权威文件。

### 4C：关系图谱

- 关系 CRUD、方向、证据和 revision 冲突；
- 论文关系图、邻接表、筛选和详情检查器；
- 子图选择和比较集合联动；
- 删除论文后的悬空引用诊断。

### 4D：主张与研究空白

- 共识、冲突和假设主张；
- 支持证据与反证；
- 从局限聚合到研究问题的证据链；
- 研究空白状态、可行性、风险和验证计划。

### 4E：综合分析工作台

- 针对分析集合生成综合分析草稿；
- 综合分析纳入领域问题、各论文方法、解决程度和判断理由；
- 从结论跳转到主张、矩阵单元格和单篇证据；
- 用户编辑、保存冲突和防误覆盖；
- 为阶段 5 的 Markdown/XLSX 导出提供稳定输入。

每个子阶段独立实现、测试和验收。阶段 4E 完成前，不把“能画关系图”视为跨论文分析已经完成。

## 8. 非目标

- MVP 不自动阅读 PDF 或生成 AI 结论；
- 不把阅读问题、论文研究问题和领域问题混为一个实体；
- 不把结构化笔记拆成每条一个 Markdown 文件；
- 不因为某篇论文存在方法条目就自动判断领域问题已经解决；
- 不自动认定方法分类、共识或研究空白；
- 不用网络图节点距离表达科学相似度；
- 不直接比较口径不一致的实验数字；
- 不把被引次数、论文数量或连接度包装成论文质量；
- 不在图中塞入长笔记或大段 PDF 原文；
- 不让派生 Excel 反向覆盖权威 YAML/Markdown。

## 9. 验收底线

- 任一矩阵单元格、关系边、主张和研究空白都能追溯到论文或明确标记待补证据；
- 当前模板保持完整 Markdown，结构化条目具有稳定身份、章节和跳转锚点；
- 一个项目可维护多个问题归纳板，每篇论文的方法和解决程度分列展示；

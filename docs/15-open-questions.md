# 开放问题与默认决策

Codex 在文档不能解决时记录问题，不应因非阻塞问题停止开发。

| 问题 | MVP 默认决策 | 未来触发条件 |
|---|---|---|
| 浏览器如何选择真实本地路径？ | 本地后端路径输入/扫描；不上传 PDF | 桌面打包或 File System Access 方案 |
| 是否允许同一 PDF 加入多个项目？ | 允许，各项目独立元数据和笔记 | 需要全局论文实体去重时重构 |
| XLSX 是否权威数据？ | 否，YAML/Markdown 权威 | 用户强需求双向编辑时设计导入预览 |
| 是否自动计算 SHA-256？ | 默认快速指纹，按需严格 hash | 大规模重复检测或文件审计 |
| 是否删除项目内笔记？ | 明确确认后可删除 PaperMatrix 文件 | 版本历史/回收站需求 |
| 是否内置 PDF 查看器？ | MVP 可调用系统查看器 | 页码联动成为高频需求 |
| 是否支持自定义字段？ | MVP 固定字段 + tags | 不同学科差异明显时引入模板 schema |
| 是否需要中英文 UI？ | MVP 中文 | 发布国际版本 |
| 是否需要登录？ | 本地单用户不需要 | 监听非 localhost 或多人协作 |
| 是否自动获取 DOI 元数据？ | MVP 不联网自动获取 | L2 可选、用户明确触发 |
| 关系图使用什么实现？ | 阶段 4 优先 Cytoscape.js，并提供邻接表；实现切片中以性能和可访问性验证后锁定 | 300 节点子图仍无法流畅操作 |
| 什么算“领域共识”？ | 至少两篇独立论文有支持证据；一篇只显示单篇发现 | 学科需要更严格证据等级时引入可配置规则 |
| 分析集合保存动态筛选还是固定论文？ | 保存解析后的固定论文 ID，并附筛选快照 | 用户需要自动滚动更新综述时增加动态集合 |
| 结构化条目是否拆成独立 Markdown 文件？ | 不拆；保留当前模板的完整 Markdown，在正文内维护稳定条目标记，YAML 保存确认投影 | 仅在无法可靠往返时重新评估存储格式 |
| 阅读问题、论文研究问题和领域问题是否共用模型？ | 不共用；分别使用 questions、结构化条目和 problem-syntheses | 仅共享统一证据引用结构 |
| 问题归纳表如何展示论文贡献？ | 每篇论文固定分为“方法”和“解决程度”两个独立单元格，贡献记录仍是一个原子对象 | 超宽矩阵通过列组折叠、分页和等价列表解决 |

## 需要用户最终决定但不阻塞阶段 0 的事项

- UI 品牌色与图标；
- 项目删除是否增加“回收站”而非直接清理；
- Windows 路径输入是否需要专门引导；
- 首个 MVP 发布平台优先级；
- 是否需要导出 Word/PPT 模板。

# 测试与质量策略

## 1. 质量门禁

任何阶段合并前必须通过：

- 后端 pytest；
- Ruff lint 与格式检查；
- mypy；
- 前端 ESLint；
- TypeScript typecheck；
- Vitest；
- 前端生产构建；
- 契约一致性检查；
- 关键端到端冒烟测试。

## 2. 测试金字塔

### 单元测试

- 路径规范化与允许根；
- slug、ID 和字段校验；
- revision 冲突；
- schema 版本迁移；
- 完整 Markdown 条目标记的解析、保留和往返序列化；
- 来源笔记 revision 与结构化投影不同步检测；
- 条目关系方向、反向引用和悬空引用；
- 领域问题、论文研究问题和阅读问题的类型边界；
- 问题归纳中方法/解决程度双列组装；
- 解决程度七态校验以及“存在方法不自动判定已解决”；
- CSV 公式注入防护；
- 矩阵行转换；
- 分析集合固定论文 ID 和缺失引用；
- 实验可比性判定与原因；
- 共识最少支持论文规则；
- 图子图筛选与邻接表等价；
- 错误码映射。

### Repository 集成测试

在 pytest `tmp_path` 中创建真实工作区：

- 创建、读取和更新项目；
- 原子写入；
- 锁超时；
- 损坏 YAML；
- 未知 schema 版本；
- 外部修改冲突；
- Windows/macOS/Linux 路径样例。

### Service 测试

- 导入正常 PDF；
- 无元数据 PDF；
- 损坏/加密 PDF；
- 重复路径和重复指纹；
- 源文件移动后重连；
- 删除记录不删除 PDF；
- 多项目引用同一 PDF；
- 导出成功和失败回滚。
- 分析集合中的论文缺失后不被静默移除；
- 单篇事实的矩阵编辑写回正确论文文件；
- 删除论文时关系、主张和空白引用按规则保留或清理；
- 综合分析重新生成不覆盖用户正文。
- 结构化笔记条目编辑后完整 Markdown 仍保留第 0–12 节和无关段落；
- 保存结构化笔记后无需调用手动解析端点即可获得候选；三级/四级语义标题块与条目一一对应，表格整体留在所属标题块中，不产生整章大块、逐行条目或字段碎片；
- 默认模板、占位表格和选项提示保持零候选，已填写的可分析模板区域无明显漏解析；
- 旧版表格行投影只在用户确认整表候选后合并，旧标签、写作用途和证据保留，旧锚点不会残留；
- 个人补充笔记首次读取、独立保存、revision 冲突和浏览器草稿恢复可验证，且不修改主笔记或源文件；
- 条目删除前返回受影响关系和问题贡献，确认后保留可诊断悬空引用；
- 领域问题映射只接受当前项目内已确认的研究问题条目；

### API 测试

- 状态码、响应 schema 和错误码；
- 不允许的路径返回 403；
- revision 冲突返回 409；
- 损坏项目文件返回可诊断 422；
- 任意路径下载不存在。

### 前端组件和页面测试

- 表单校验；
- 论文导入确认；
- 记录删除文案；
- 保存状态；
- 冲突处理；
- 筛选排序；
- 分析集合切换后各标签范围一致；
- 不可比实验不显示排名；
- 关系图和邻接表选择同步；
- 主张与研究空白证据跳转；
- 问题归纳板切换、方法/解决程度分列编辑和来源检查；
- 项目级方法、程度或证据跳转后正确展开并高亮笔记条目；
- 移动端按问题列表与桌面双列矩阵同源；
- 错误详情。

### E2E

关键路径：初始化工作区 → 创建项目 → 扫描并导入 PDF → 编辑完整结构化笔记和个人补充笔记 → 确认研究问题/方法条目 → 建立条目关系并跳回来源 → 创建分析集合 → 建立领域问题归纳板 → 分列填写各论文方法和解决程度 → 比较方法与实验 → 建立带证据关系 → 形成主张和研究空白 → 编辑综合分析 → 导出矩阵 → 删除记录 → 验证悬空引用可诊断且 PDF 仍存在。

## 3. 测试夹具

仓库内不提交真实论文。使用最小合成 PDF 夹具，或测试运行时生成。每个夹具说明用途：正常、无元数据、损坏、加密、超大模拟。

## 4. 数据安全测试

必须有明确测试：

- 删除记录前后 PDF hash 一致；
- 更新元数据不改变 PDF mtime；
- 符号链接指向允许根外时拒绝；
- 临时写失败时旧 YAML 完整保留；
- 两个 revision 同时写只有一个成功；
- 导出失败不覆盖已有导出。

## 5. 性能测试

生成 1,000 篇论文的合成项目，测量：

- 列表读取；
- 筛选和排序；
- XLSX 导出；
- 项目总览统计。
- 100–300 节点关系子图布局与交互；
- 1,000 篇项目中的分析集合切换和矩阵组装。
- 领域问题 × 论文双列矩阵的分页、列组折叠和按问题列表。

MVP 不需微优化，但应避免每次请求重复解析全部 Markdown 正文。矩阵主要读取 YAML 摘要；图接口只返回当前子图，不把全项目关系无条件推给前端。

## 6. 可观测性

开发模式输出结构化日志；测试断言关键事件而非完整文案。诊断接口只提供状态、计数、错误码和脱敏路径。

# 前端设计规范

## 1. 技术原则

- Vue 3 Composition API；
- TypeScript strict；
- `<script setup>`；
- Vue Router 管理页面；
- Pinia 只管理跨页面状态；
- Element Plus 提供表格、表单、对话框和通知；
- API 类型集中定义，不在组件中散落匿名对象；
- 不把持久数据只保存在 localStorage。

## 2. 路由

## 3. 页面职责

### 项目列表

卡片或紧凑表格展示名称、主题、论文数、精读数、最近更新和状态。提供新建、归档过滤和打开项目。

### 项目总览

展示进度指标、最近论文、待补充字段、缺失 PDF、研究空白数量和快捷入口。

### 论文矩阵

- 表格虚拟化或分页；
- 固定标题、年份、会议和阅读状态等关键列；
- 列显隐和列宽记忆；
- 搜索、标签、状态、年份、写作用途筛选；
- 支持多选并进入比较页；
- 单元格编辑失败时保留旧值并提示。
- 添加入口使用分段控件区分单个 PDF、文件路径、目录扫描和仅建记录；
- 单个 PDF 明示“仅读取、不留存”，无长期路径时标记未关联；
- 来源状态支持正常、未关联、缺失、已变化和无法解析。
- 基础信息支持发表载体、署名单位、发表时间、阅读时间、被引次数、语言、关键词与摘要；
- 每篇论文可设置项目内分组，并按分组筛选。

### 论文详情

分区显示书目信息、来源状态、结构化摘要、实验和写作用途。提供打开原 PDF、进入完整笔记、重新关联和移除记录。

### 笔记编辑器

结构化笔记继续显示当前模板的完整 Markdown，并提供“完整文档/条目模式”切换；两种模式编辑同一份内容。个人补充笔记独立为自由 Markdown。必须支持：

- 自动保存延迟；
- 手动保存；
- 未保存标记；
- revision 冲突；
- 保存失败后复制内容；
- 模板章节导航；
- 快速插入页码、图号、表号条目。
- 条目稳定 ID、模板章节、来源锚点和反向引用；
- 论文研究问题作为正式 `research_problem` 条目；
- 从条目关系或项目级分析跳转后展开章节、滚动定位并高亮；
- 外部 Markdown 修改后的候选差异审阅；
- 个人补充笔记独立 revision、冲突和失败恢复。

新论文登记时已保存默认模板并显示 revision 1；旧记录缺少笔记文件时仍显示 revision 0 的兼容提示。两种情况都不得展示或允许导入模板自带的示例文字。

当前双模式实现中，进入条目模式前必须先保存完整文档。论文详情加载和每次保存后自动解析候选，不弹窗打断编辑；界面显示“已自动解析”或待审阅数量，用户点击审阅只负责确认是否写入论文 YAML。确认条目列表使用独立滚动区域，显示已同步、待审阅或来源缺失状态，并提供复选、全选、单条删除和批量删除。只有已同步条目可编辑。保存条目只更新当前稳定锚点片段，切换条目或模式时对未保存草稿进行离开确认。完整文档被外部修改后，用户必须在候选审阅窗口明确选择新增、修改或删除候选；删除候选默认不选中，系统不会自动删除投影或用投影覆盖 Markdown。个人补充笔记使用独立标签、revision 和自动保存；浏览器可恢复与当前服务端版本匹配的本地草稿，版本不匹配时保留草稿并要求用户复制、重载和合并。

### 跨论文分析工作台

顶部始终显示当前分析集合、纳入论文数量、缺失引用和准备度。主区域使用标签页切换：文献、问题归纳、方法与挑战、实验、关系、主张与空白、综合分析。

- 分析集合可由论文筛选、分组或勾选结果创建；
- 切换集合时所有矩阵、图和综合分析同步切换；
- 问题归纳支持多个归纳板；每篇论文在每个领域问题下固定显示“方法”和“解决程度”两个独立单元格；
- 点击问题归纳单元格打开贡献检查器，方法、程度、理由、证据、反证和条件分别可检查；
- 方法存在不自动改变解决程度，领域问题映射和程度均需用户确认；
- 矩阵单元格点击后打开来源检查器，编辑写回论文 YAML；
- 实验页先显示可比性，再显示结果；不可比项不提供排名；
- 关系页使用全宽画布、紧凑工具栏和右侧详情检查器，不把图放入装饰卡片；
- 图和热力矩阵都有等价表格，移动端默认表格；
- 主张和研究空白展示支持、反证、待补证据和适用范围；
- 综合结论支持跳回来源条目与证据位置。
- 移动端的问题归纳默认使用按领域问题展开的等价列表。

关系图实现优先评估 Cytoscape.js，使用成熟布局插件；禁止手写图布局。节点、边、筛选和选择使用局部响应式状态，避免把整个图实例放入 Pinia。

## 4. 状态管理

建议 Store：

- `appStore`：后端状态、版本、全局通知；
- `workspaceStore`：工作区和允许根；
- `projectStore`：当前项目及列表；
- `paperStore`：列表查询、选择和当前论文；
- `preferencesStore`：列显隐、筛选和界面偏好。

不要把整个笔记正文长期复制到多个 Store。编辑器内部维护草稿，并在路由离开时提示。

## 5. API 客户端

统一处理：

- base URL；
- JSON 序列化；
- 超时和 AbortController；
- `request_id`；
- 后端错误码；
- 401/403 预留；
- 409 revision 冲突；
- 网络断开提示。

## 6. 类型和验证

- API 响应至少在边界做轻量运行时检查；
- 表单使用明确 schema；
- 年份、评分、URL 和路径输入进行前端基础校验，但后端仍是最终权威；
- 不信任路由参数。

## 7. 测试重点

- 路由守卫和未初始化工作区；
- 项目创建表单；
- 扫描候选与导入确认；
- 删除记录提示“不会删除 PDF”；
- 不符合当前 Paper Schema 的记录单独显示，不把正常论文误报为空；只提供明确确认后的元数据删除，并再次说明原 PDF 不受影响；
- 笔记自动保存和冲突；
- 矩阵筛选与列设置；
- 分析集合范围一致性；
- 实验可比性与不可比警告；
- 图和邻接表的数据等价；
- 主张证据回溯；
- 错误码到用户提示的映射。

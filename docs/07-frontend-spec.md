# 前端设计规范

## 1. 技术原则

- Vue 3 Composition API；
- TypeScript strict；
- `<script setup>`；
- Vue Router 管理页面；
- Pinia 只管理跨页面状态；
- Element Plus 提供表格、表单、对话框和通知；
- API 类型集中定义，不在组件中散落匿名对象；
- 不把持久数据只保存在 localStorage。

## 3. 页面职责

### 项目列表

卡片或紧凑表格展示名称、主题、论文数、精读数、最近更新和状态。提供新建、归档过滤和打开项目。

### 项目总览

展示进度指标、最近论文、待补充字段、缺失 PDF、研究空白数量和快捷入口。

### 论文矩阵

- 表格虚拟化或分页；
- 固定标题、年份、会议和阅读状态等关键列；
- 列显隐和列宽记忆；
- 搜索、标签、状态、年份、写作用途筛选；
- 支持多选并进入比较页；
- 单元格编辑失败时保留旧值并提示。
- 添加入口使用分段控件区分单个 PDF、文件路径、目录扫描和仅建记录；
- 单个 PDF 明示“仅读取、不留存”，无长期路径时标记未关联；
- 来源状态支持正常、未关联、缺失、已变化和无法解析。
- 基础信息完整覆盖模板第 0 节：标题/简称、作者、单位、载体、发表与阅读时间、被引次数、语言、关键词、论文/代码/数据链接、阅读状态、重要程度、一句话总结、摘要和项目分组；
- 每篇论文可设置项目内分组，并按分组筛选。

### 论文详情

分区显示书目信息、来源状态、结构化摘要、实验和写作用途。提供打开原 PDF、进入完整笔记、重新关联和移除记录。

### 笔记编辑器

结构化笔记继续显示当前模板的完整 Markdown，并提供“完整文档/条目模式”切换；两种模式编辑同一份内容。个人补充笔记独立为自由 Markdown。必须支持：

- 自动保存延迟；
- 手动保存；
- 未保存标记；
- revision 冲突；
- 保存失败后复制内容；
- 模板章节导航；
- 快速插入页码、图号、表号条目。
- 条目稳定 ID、模板章节、来源锚点和反向引用；
- 论文研究问题作为正式 `research_problem` 条目；
- 从条目关系或项目级分析跳转后展开章节、滚动定位并高亮；
- 条目关系登记簿以“来源 → 关系 → 目标”展示方向，支持按任一条目查看出向与反向引用；缺失端点同时显示文字警告，仍存在的端点通过 project/paper/item ID 跳回条目模式；
- 论文矩阵默认展示跨论文分析矩阵，可切换项目全部论文或已保存分析集合；冻结论文列并在局部容器内横向滚动，移动端不带动整页漂移；
- 准备度显示 `n/4` 与缺失的“方法/实验/局限/证据”文字，不使用完整度暗示论文质量；每行可编辑基础 YAML 或进入结构化条目模式；
- 外部 Markdown 修改后的候选差异审阅；
- 个人补充笔记独立 revision、冲突和失败恢复。

新论文登记时已保存默认模板并显示 revision 1；旧记录缺少笔记文件时仍显示 revision 0 的兼容提示。两种情况都不得展示或允许导入模板自带的示例文字。

当前三种笔记模式中，进入条目模式或收藏前必须先保存完整文档。论文详情加载和每次保存后自动解析候选，不弹窗打断编辑；界面显示待审阅数量，用户点击审阅只负责确认外部或旧笔记变化是否写入论文 YAML。模板目录使用独立滚动区域，按章节列出全部固定槽位，并显示待填写、已填写、待同步或位置缺失状态。收藏只适用于已有稳定投影的条目，使用论文 revision 保存，不修改 Markdown 正文。固定槽位即使为空也可编辑，保存时只更新原模板标题下的正文；可扩展条目继续使用稳定锚点片段。切换条目或模式时对未保存草稿进行离开确认。完整文档被外部修改后，用户必须在候选审阅窗口明确选择新增、修改或删除候选；删除候选默认不选中，系统不会自动删除投影或用投影覆盖 Markdown。个人补充笔记使用独立标签、revision 和自动保存；浏览器可恢复与当前服务端版本匹配的本地草稿，版本不匹配时保留草稿并要求用户复制、重载和合并。
新内容默认从条目模式录入：第 1–8 节所有模板项在空白状态下就会出现，用户逐项填写。研究背景等固定项不提供“新增同类条目”；多点内容直接在当前正文列举。可拓展菜单只提供 2.2 代表性文献、第 4 章挑战和第 5 章创新点；它们分别沿用模板的文献、挑战和创新分析字段。新增成功后目录按 Markdown 真实位置显示，并直接进入新增条目的编辑态。旧笔记和外部编辑仍使用候选审阅。桌面端条目模式采用“模板目录 / 当前正文 / 论文证据目录”三栏，证据栏独立滚动；移动端依次堆叠为等价操作。证据栏提供“添加证据”，默认可关联当前已保存条目，并明确写入 `E-xxx` 编号引用。

分析条目的系统分类用于稳定筛选和后续分析；用户可另设自定义显示标签和自由标签。第 11 节先维护带 `E-001` 等编号的独立证据目录，条目只能明确勾选这些证据引用，不能按系统分类自动猜测归属。

### 跨论文分析工作台

顶部始终显示当前分析集合、纳入论文数量、缺失引用和准备度。主区域使用标签页切换：文献、问题归纳、方法与挑战、实验、关系、主张与空白、综合分析。

- 分析集合可由论文筛选、分组或勾选结果创建；
- 切换集合时所有矩阵、图和综合分析同步切换；
- 问题归纳支持多个归纳板；每篇论文在每个领域问题下固定显示“方法”和“解决程度”两个独立单元格；
- 点击问题归纳单元格打开贡献检查器，方法、程度、理由、证据、反证和条件分别可检查；
- 方法存在不自动改变解决程度，领域问题映射和程度均需用户确认；
- 矩阵单元格点击后打开来源检查器，编辑写回论文 YAML；
- 实验页先显示可比性，再显示结果；不可比项不提供排名；
- 关系页使用全宽画布、紧凑工具栏和右侧详情检查器，不把图放入装饰卡片；
- 图和热力矩阵都有等价表格，移动端默认表格；
- 主张和研究空白展示支持、反证、待补证据和适用范围；
- 综合结论支持跳回来源条目与证据位置。
- 移动端的问题归纳默认使用按领域问题展开的等价列表。

关系图实现优先评估 Cytoscape.js，使用成熟布局插件；禁止手写图布局。节点、边、筛选和选择使用局部响应式状态，避免把整个图实例放入 Pinia。

## 4. 状态管理

建议 Store：

- `appStore`：后端状态、版本、全局通知；
- `workspaceStore`：工作区和允许根；
- `projectStore`：当前项目及列表；
- `paperStore`：列表查询、选择和当前论文；
- `preferencesStore`：列显隐、筛选和界面偏好。

不要把整个笔记正文长期复制到多个 Store。编辑器内部维护草稿，并在路由离开时提示。

## 5. API 客户端

统一处理：

- base URL；
- JSON 序列化；
- 超时和 AbortController；
- `request_id`；
- 后端错误码；
- 401/403 预留；
- 409 revision 冲突；
- 网络断开提示。

## 6. 类型和验证

- API 响应至少在边界做轻量运行时检查；
- 表单使用明确 schema；
- 年份、评分、URL 和路径输入进行前端基础校验，但后端仍是最终权威；
- 不信任路由参数。

## 7. 测试重点

- 路由守卫和未初始化工作区；
- 项目创建表单；
- 扫描候选与导入确认；
- 删除记录提示“不会删除 PDF”；
- 不符合当前 Paper Schema 的记录单独显示，不把正常论文误报为空；只提供明确确认后的元数据删除，并再次说明原 PDF 不受影响；
- 笔记自动保存和冲突；
- 矩阵筛选与列设置；
- 分析集合范围一致性；
- 实验可比性与不可比警告；
- 图和邻接表的数据等价；
- 主张证据回溯；
- 错误码到用户提示的映射。

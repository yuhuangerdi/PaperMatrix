# 安全与隐私设计

## 1. 威胁模型

MVP 是本机单用户应用，但仍需防范：

- 恶意或错误路径导致读取任意文件；
- 符号链接绕过允许根；
- 浏览器或第三方网页访问本机服务；
- 恶意 PDF 触发解析库问题；
- 并发保存导致元数据丢失；
- 导出公式注入；
- 日志泄露论文路径、标题或笔记；
- 删除操作误伤源 PDF；
- 未来 AI 模块未经同意上传文件。

## 2. 网络边界

- 默认监听 127.0.0.1；
- CORS 仅允许明确的前端开发源；
- 生产同源部署优先；
- 不使用 `Access-Control-Allow-Origin: *`；
- 对写操作校验 Origin/Host；
- 若以后监听非本地地址，必须先引入认证、HTTPS、CSRF 策略和权限审计。

## 3. 文件边界

- 工作区写权限和论文目录只读权限分离；
- 所有论文路径必须位于 `allowed_paper_roots`；
- 使用真实路径检查符号链接；
- API 不接受任意下载路径；
- 笔记跳转只接受当前项目内的 paper/item UUID，不接受客户端提供的文件路径或 Markdown 行号；
- 扫描限制文件数量、深度和单文件大小；
- 只处理 `.pdf` 且检查 MIME/文件头作为辅助，不完全信任扩展名。

## 4. PDF 安全

- 只读取基础元数据和页数；
- 禁止执行 JavaScript、启动外部程序或提取运行附件；
- 解析异常隔离为单文件失败；
- 对超大、加密或损坏 PDF 允许只登记路径；
- 定期更新并锁定解析库版本。

## 5. 表格导出安全

用户内容以 `=`, `+`, `-`, `@` 开头时，CSV/XLSX 导出必须防止公式注入。作为文本写入，必要时前置单引号，并在测试中覆盖。

## 6. 删除安全不变量

- 源 PDF 路径不进入任何删除函数；
- 删除允许目标必须位于当前项目目录；
- 删除前解析并验证目标；
- 关系清理先计算变更再写入；
- 删除条目或论文前先计算条目关系、领域问题贡献、主张和综合分析的受影响引用，确认后保留可诊断悬空引用；
- 测试使用哨兵 PDF，验证删除记录后文件仍存在且 hash 不变。

## 7. 隐私

- MVP 不向互联网发送论文、笔记、标题或路径；
- 不内置遥测；
- 错误报告由用户主动导出；
- 未来 AI/翻译调用前必须显示将上传的内容范围、服务商和可能成本；
- API Key 仅从环境变量或系统密钥存储读取，不写入项目文件。

## 8. 依赖和供应链

- 锁定依赖；
- 启用依赖漏洞扫描；
- 前后端构建不运行来源不明脚本；
- 避免不必要大型依赖；
- 在发布前生成依赖清单。

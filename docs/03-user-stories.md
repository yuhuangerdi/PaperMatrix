# 用户故事

## 项目管理

### US-001 新建研究项目

作为研究生，我希望为“LLM 自动化渗透测试”新建项目，以便把相关论文、对比表和研究空白集中管理。

验收：创建后出现标准项目目录和 `project.yaml`；无需数据库。

### US-002 查看项目进度

作为用户，我希望看到项目论文数、精读数、已汇报数和最近更新，以便决定下一步读什么。

## 论文导入

### US-010 引用已有 PDF

作为用户，我希望把已有文件夹中的 PDF 加入项目，但不复制论文，以便继续使用自己的文件整理方式。

验收：源 PDF 大小、修改时间和路径不变；项目仅新增元数据文件。

### US-011 重新关联移动后的 PDF

作为用户，我移动了原 PDF，希望重新选择路径而不丢失笔记。

验收：只更新 `source.path` 和指纹，论文 ID、笔记和关系不变。

### US-012 安全删除记录

作为用户，我希望从项目中移除错误导入的论文，同时确保原 PDF 不被删除。

验收：确认对话明确说明影响；后端没有删除源文件的代码路径。

## 阅读和笔记

### US-020 按老师要求精读

作为需要汇报的学生，我希望笔记模板直接包含背景、现有方案、本文框架、挑战、创新、细节和实验，以免遗漏老师关心的内容。

### US-021 保存证据定位

作为论文写作者，我希望记录观点对应页码、图号和表号，以便以后引用时快速回到原文。

### US-022 区分作者观点和个人判断

作为研究者，我希望分别记录作者声称的局限和我发现的局限，以便做批判性分析。

### US-023 保留完整笔记并独立关联条目

作为研究者，我希望继续用当前完整 Markdown 模板阅读和导出，同时把其中的研究问题、方法、实验等条目独立关联，并能从关联处跳回原位置。

### US-024 记录个人补充笔记

作为研究者，我希望把不适合固定模板的自由想法单独保存，而不破坏结构化笔记的完整章节。

## 比较和选题

### US-030 比较同类方法

作为用户，我希望选择多篇论文并比较方案路线、挑战、模块和缺点，以便写相关工作。

### US-031 比较实验

作为用户，我希望比较数据集、基线、指标和开源情况，并看到“实验条件不同不可直接比较”的提示。

### US-032 建立研究空白

作为用户，我希望把多篇论文重复出现的局限聚合成候选研究问题，并记录潜在方法和验证实验。

### US-033 归纳领域问题和各论文解法

作为用户，我希望建立多个领域问题归纳表，把不同论文的研究问题映射到统一领域问题，并在每篇论文下分别查看“方法”和“解决程度”，点击后回到单篇笔记证据。

## 汇报和写作

### US-040 生成汇报摘要

作为用户，我希望从已填内容生成一页摘要，以便快速制作汇报 PPT。

### US-041 导出写作素材

作为用户，我希望按 INTRO、RELATED、BASELINE、LIMITATION 等标签筛选并导出，以便写论文不同章节。

## 维护和恢复

### US-050 发现损坏文件

作为用户，某个 YAML 被外部工具改坏时，我希望应用明确指出文件和错误，而不是覆盖我的数据。

### US-051 诊断缺失路径

作为用户，我希望在诊断页看到哪些 PDF 已移动、哪些导出失败以及如何修复。

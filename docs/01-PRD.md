# 产品需求文档（PRD）

## 1. 产品范围

PaperMatrix MVP 是运行在用户本机的 Web 应用。Python 后端管理本地项目文件，Vue 前端提供浏览器界面。默认单用户，不提供账号系统和云同步。

## 2. 核心实体

- 工作区（Workspace）：PaperMatrix 管理数据的根目录；
- 项目（Project）：围绕一个研究主题、课题、汇报或论文写作组织；
- 论文（Paper）：对用户已有 PDF 的引用及其结构化元数据；
- 笔记（Paper Note）：保留当前模板的完整结构化 Markdown 及独立个人补充 Markdown；
- 结构化条目（Note Item）：完整笔记中具有稳定 ID、章节、证据和来源锚点的研究问题、方法、实验等内容；
- 条目关系（Item Link）：同篇或跨篇结构化条目之间的有向语义关系；
- 问题归纳板（Problem Board）：绑定分析集合的一张领域问题归纳表；
- 领域问题（Field Problem）：用户综合多篇论文研究问题后确认的统一问题定义；
- 论文贡献（Paper Contribution）：某篇论文针对领域问题的方法、解决程度、理由和证据；
- 关系（Relation）：论文之间的改进、对比、共享数据集等关系；
- 分析集合（Analysis Scope）：一次可复现跨论文分析明确纳入的论文集合；
- 矩阵（Matrix）：跨论文比较视图与导出文件；
- 主张（Claim）：由多篇论文支持、反驳或仍待验证的跨论文判断；
- 综合分析（Synthesis）：针对主题的跨论文总结和研究空白。

## 3. 功能需求

### FR-001 工作区设置

- 首次启动时选择后端可访问的工作区根目录；
- 检查读写权限；
- 配置一个或多个允许扫描论文的根目录；
- 显示当前部署模式和路径含义；
- 不自动扫描整块磁盘。

### FR-002 项目管理

- 创建项目：名称、研究主题、描述、标签、阶段；
- 列表显示论文数、已精读数、最近修改时间；
- 编辑项目信息；
- 归档项目；
- 仅允许删除空项目，或在明确确认后删除 PaperMatrix 项目文件；
- 删除项目时不得触碰引用 PDF。

### FR-003 论文导入

- 用户输入或粘贴后端可访问的目录路径；
- 后端列出该目录中的 PDF，可选择是否递归；
- 用户选择论文并登记到项目；
- 导入时只保存路径引用和文件指纹，不复制；
- 尝试读取标题、页数、文件大小和 PDF 元数据；
- 无元数据时允许手工补充；
- 检测同项目内重复路径和相同指纹；
- 一个 PDF 可关联多个项目，但每个项目有独立笔记。

### FR-004 论文状态

支持：未读、粗读、精读、已总结、已汇报。支持 A/B/C/D 优先级、1–5 重要性和复现价值评分。

### FR-005 单篇结构化笔记

结构化笔记必须始终保存为一份完整 Markdown，并继续使用当前模板第 0–11 节。系统可以在模板内部维护独立条目，但不得把每个条目拆成单独 Markdown 文件。完整文档模式和条目模式编辑同一份内容；个人自由笔记独立保存并可在导出时合并。

条目模式默认预载模板第 1–8 节全部填写项，空项也显示；固定项只在模板原位置填写，多点内容在槽位内部列举。仅代表性文献等明确的一对多分组允许新增独立知识单元。第 0 节不进入条目，只能在概览编辑并同步显示；第 11 节是论文级证据目录，在条目模式独立展示，添加证据时可同时关联当前条目。旧笔记和外部修改继续通过候选审阅进入结构化投影。

笔记必须覆盖：

- 背景、问题和重要性；
- 现有方案分类及 3–5 篇经典文献；
- 本文思路与框架；
- 挑战和难点；
- 流程及创新点 3+1；
- 具体模块、流程和技术细节；
- 实验、基线、指标、结果、源码和数据；
- 批判性评价；
- 与其他论文关系；
- 写作用途和研究启发；
- 关键页码、图表和引用证据。

每个适合检索、关联或比较的条目具有稳定 ID、模板章节、顺序、来源锚点和来源笔记 revision。论文研究问题是结构化笔记中的 `research_problem` 条目。条目可以建立同篇或跨篇的有向关系、显示反向引用，并从项目级视图稳定跳回完整笔记。

证据先在第 11 节按 `E-001` 等唯一编号登记；条目正文通过 `证据：E-001` 引用，确认后的 YAML 条目只保存证据 UUID 引用。阅读问题只由问题栏目和 `questions/<paper-id>.yaml` 管理，不在笔记模板中建立索引。

### FR-006 文献矩阵

- 一篇论文一行；
- 可搜索、筛选、排序、固定表头、列显隐；
- 支持核心字段快速编辑；
- 点击进入论文详情；
- 支持保存个人视图偏好；
- 支持导出 CSV/XLSX。

### FR-006A 领域问题归纳

- 严格区分阅读问题、论文研究问题和领域问题；
- 一个项目可以维护多个绑定分析集合的问题归纳板；
- 一个领域问题可以由多篇论文中经确认的研究问题条目共同映射；
- 每个“领域问题 × 论文”分别记录问题条目、方法条目、实验条目、解决程度、判断理由、支持证据、反证和成立条件；
- 问题归纳表以领域问题为行，每篇论文固定分为“方法”和“解决程度”两个独立单元格；
- 解决程度支持解决、部分解决、间接缓解、尝试但未解决、未涉及、不适用和未知，并始终显示文字和理由；
- 方法存在不等于问题已经解决，系统不得从关键词、条目数量或论文数量自动生成解决程度；
- 任一方法、程度和证据可跳回完整结构化笔记的对应章节和条目；
- 表格同时提供移动端和键盘可操作的等价列表。

### FR-007 方法对比

- 每次比较必须选择或建立分析集合；
- 按研究问题和方案路线分组；
- 方法分类保存定义、纳入条件和排除条件，不只保存分类名称；
- 记录代表文献、核心思路、优点、缺点；
- 支持挑战—方案能力矩阵；
- 矩阵单元格支持已处理、部分处理、未处理、不适用和未知，并可追溯到证据；
- 支持选中论文生成对比表。

### FR-008 实验对比

- 记录环境、数据集、规模、模型、基线、指标、结果、消融、泛化、失败分析和复现性；
- 按任务定义、环境、数据、模型、工具权限、人工参与、运行次数和指标判断可比性；
- 显示可比、部分可比、不可比或未知及原因；
- 不可比结果不得排名或自动换算，未知值不得按零处理；
- 支持选择若干论文导出实验比较表。

### FR-009 研究空白

- 记录研究空白、支持论文、现有处理、未解决原因、潜在方案和验证实验；
- 支持从带证据的论文局限手动关联到研究空白；
- 记录反例、已有缓解、适用范围、可检验研究问题、失败标准和风险；
- 单篇证据只标记为线索，多篇重复局限经用户确认后才形成候选问题；
- 支持状态：线索、待验证、候选选题、已排除。

### FR-010 论文关系

- 支持固定关系类型：改进自、对比于、使用相同数据集、解决相同问题、使用相似框架、解决其局限、结论冲突、可组合、可作为基线；
- 关系包含方向、描述和证据；
- 提供关系网络图与等价邻接表；
- 图的筛选和布局不修改业务关系，节点多选可建立新的分析集合。

### FR-010A 跨论文主张

- 维护共识、争议和假设；
- 记录适用范围、支持证据、反证、用户判断、信心和状态；
- 只有一篇论文支持时显示为单篇发现，不能标记为领域共识；
- 支持从主张跳回论文条目及页码、图表证据。

### FR-011 汇报和综合分析

- 生成一页汇报摘要草稿；
- 生成主题综合分析 Markdown 模板；
- 内容来自用户已填写字段，不进行无来源自动推断；
- 缺失字段以待补充标记呈现。
- 综合分析绑定分析集合并显示纳入范围；
- 重新生成默认提供预览或新版本，不静默覆盖用户编辑正文；
- 结论可以跳回主张、矩阵单元格和单篇证据。
- 综合分析纳入当前分析集合中的领域问题、各论文方法、解决程度、判断理由、反证和共同未决问题。

### FR-012 导出

- 项目总表 CSV/XLSX；
- 方法对比、实验对比、研究空白 CSV/XLSX；
- 单篇笔记和一页汇报 Markdown；
- 主题综合分析 Markdown；
- 导出文件写入项目 `exports/`，也可浏览器下载；
- 导出失败不得损坏原有文件。

## 4. 非功能需求

### NFR-001 数据透明

项目数据必须能用普通文本编辑器或 Excel 打开。不得把唯一数据隐藏在浏览器缓存或数据库中。

### NFR-002 性能

目标规模：单项目 1,000 篇论文、工作区 50 个项目。列表初次载入在普通本地电脑上目标小于 2 秒；搜索和筛选目标小于 300 毫秒。

### NFR-003 可靠性

- 原子写入；
- 并发锁；
- 文件损坏时进入只读诊断，不静默覆盖；
- 已发布 Schema 的旧版本必须可直接读取迁移或具备显式升级路径；单个无法迁移的记录必须隔离展示，不能阻断同项目其他记录；
- 保存失败保留前端未提交内容；
- 源 PDF 永远只读。

### NFR-004 可移植性

支持 macOS、Windows 和 Linux 的本地后端。路径存储支持绝对路径和工作区相对路径。

### NFR-005 可访问性

核心功能可通过键盘操作；表单有标签；错误不只依赖颜色表达。

### NFR-006 可测试性

文件逻辑可在临时目录中独立测试；API、服务和仓储层可替换；前端 API 调用可 mock。

## 5. MVP 不包含

- 桌面端打包；
- 登录、云同步和多人协作；
- 浏览器直接访问访问者本机任意路径；
- PDF 内容自动上传；
- 全自动翻译和 LLM 分析；
- 用户手工修改 XLSX 后的双向实时同步；
- 引文管理器完整替代品；
- PDF 原文编辑和批注写回。

# 结构化笔记条目模式

## 目标与数据边界

条目模式用于把一篇论文的完整阅读笔记变成可检索、可比较、可关联的分析单元，同时不牺牲 Markdown 的连续可读性。

每篇论文保留两份不同职责的权威数据：

- `notes/<paper-id>.md` 是结构化笔记的权威正文。它保留第 0–12 节、用户的段落、列表、表格和章节顺序，是阅读和写作时应直接查看的完整 Markdown。
- `papers/<paper-id>.yaml` 中的 `structured_summary.items` 是经确认的分析投影。它保存适合检索、矩阵和跨论文分析的简短结构化信息，不取代或重建正文。

因此，系统不会把每个条目拆成单独 Markdown 文件，也不会用 YAML 中较旧的摘要静默覆盖用户刚编辑过的笔记。未确认的解析候选只存在于 API 响应和前端审阅状态中，不是权威数据。

## 从完整笔记到候选

论文详情加载、完整笔记保存、条目保存或候选确认后，前端都会读取 `GET .../note/items`。该接口解析当前保存的 Markdown，返回已确认条目、候选、警告和待审阅数量；它不会弹出窗口，也不会写入 `paper.yaml`。保留的解析端点只用于兼容既有客户端或显式刷新。

解析器使用模板的语义标题和表格结构，而不是按固定字符数切块：

- 每个有实际内容的三级或四级标题块默认生成一个候选。块内的段落、列表、键值对会保留在同一个候选中。
- 结构化表格按每个有效数据行生成一个候选。例如“现有方法分类”“框架组成”和“主要实验结果”表格中的每行都是独立对象。
- 现有方法分类、本文切入点、整体框架、大致流程、6.1–6.9 技术步骤、开源情况、论文优点和可靠性检查等模板区域会按对应语义类型解析。
- 第 0、9、10、11、12 节不是普通分析条目来源：它们分别承载元数据、关系候选、写作用途、证据和阅读问题。

候选类型包括论文研究问题、场景、方法、方法组件、机制、挑战、创新、贡献、实验、发现、作者局限、阅读者局限和结论成立条件。证据表中的页码、图表和定位说明会按类型附加到相关候选；没有证据不会阻止候选出现，但后续分析会显示待补证据。

### 模板占位内容为何不会被解析

解析器会过滤默认模板的示例、空白值、选项提示和占位表格，例如“模块 A”“公开 / 未公开 / 部分公开”以及示例流程。尚未保存的默认模板固定返回零候选和填写提示。这样“自动解析”只处理用户实际写入的内容，不会把模板脚手架误存为研究结论。

## 身份、位置与来源指纹

每个候选首先使用论文 ID、类型、来源标题、标题和内容生成确定性的 UUID。候选被确认后，这个 UUID 成为稳定 `item_id`，并记录以下来源信息：

- `section_key`、`section_title` 和 `section_order`：表示它属于哪一个模板章节以及在章节中的顺序；
- `source_anchor`：`papermatrix:item:<item-id>`，用于稳定定位；
- `source_note_revision`：确认或同步时的笔记版本；
- `source_fingerprint`：条目正文片段的 SHA-256 指纹。

确认标题块时，系统会在标题上一行插入不可见 HTML 注释，例如：

```markdown
<!-- papermatrix:item:xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx -->
### 3.1 核心思路
```

确认表格行时，标记放在该行第一个单元格中。标记不改变正常 Markdown 渲染，也不会要求用户记忆行号。后续解析优先恢复这个 ID，因此笔记其他部分增加段落或移动空行时，条目的身份仍能保持。

没有确认过的候选没有写入锚点。用户也可以手动新建分析条目；这类条目允许存在，但没有正文来源锚点，不能冒充从笔记自动提取的内容。

## 条目模式如何编辑正文

完整文档模式与条目模式始终编辑同一份 `notes/<paper-id>.md`。

条目模式打开时，系统依据稳定锚点截取对应的标题块或表格行，隐藏锚点本身后显示给用户编辑。保存时会再次验证笔记版本、论文版本和来源指纹：

1. 找到匹配的稳定锚点；
2. 确认标题层级或表格行仍可安全替换；
3. 仅替换该条目片段，保留锚点、其他章节、空行和无关段落；
4. 重新解析更新后的 Markdown；
5. 只有原 `item_id` 和条目类型仍能保留时，才同步更新 YAML 投影。

若锚点缺失、条目类型因编辑而改变，或用户提交的文本不能安全作为原片段替换，系统拒绝写入并要求回到完整文档检查。这避免了局部编辑意外吞掉整章内容。

## 自动解析与人工确认

自动解析解决的是重复劳动：用户保存一份已填写的结构化笔记后，可以立刻看到待审阅数量，不再需要先点击“从笔记提取”。

人工确认仍然必要，因为解析器只根据 Markdown 结构识别候选，不能可靠判断某一段是否值得进入跨论文矩阵、是否需要合并为一个概念，或是否应当作为正式研究结论。用户在审阅中可以选择导入、同步已修改条目或忽略候选。

确认才会发生两项持久化修改：

1. 在 Markdown 中写入稳定锚点；
2. 在 `paper.yaml` 中新增或同步 `structured_summary.items` 投影。

所以“自动解析”不会自动改变论文事实，也不会替用户做学术判断。

## 版本、锁与外部修改保护

笔记和论文 YAML 都有独立 `revision`。保存或确认请求必须提交用户看到的预期 revision；如果其他窗口或外部编辑已写入新版本，系统返回冲突而不是覆盖较新的内容。

每次可变文件写入遵循同一流程：

1. 校验内容和 Schema；
2. 获取文件锁；
3. 再次核对 revision；
4. 在同目录写入临时文件并刷新到磁盘；
5. 使用原子替换完成写入，并在可用时同步目录元数据。

这保证进程中断时旧文件仍然完整，并避免并发写入产生半份 YAML 或 Markdown。

除 revision 外，条目投影还保存来源片段的 SHA-256 指纹。完整笔记被外部程序或另一个编辑窗口修改后，重新解析会把已有条目标记为已同步、待审阅或来源缺失：

- **已同步**：当前片段指纹与投影一致；
- **待审阅**：锚点还在，但正文内容已变化；
- **来源缺失**：找不到对应锚点或片段。

待审阅内容需要用户明确确认才会更新 YAML；来源缺失不会自动删除已有投影。这让外部 Markdown 编辑保持可恢复、可诊断，也不会静默抹掉跨论文分析已经引用的条目。

## 对维护者的约束

- 新增可解析章节时，必须同时更新解析器映射、模板过滤、测试和 API/前端说明。
- 改动 `structured_summary.items` Schema 时，必须提供旧版迁移或可测试升级路径；不能因为版本升级而让旧论文不可读取。
- 任何新的项目级关系、矩阵或综合分析都应引用 `project_id`、`paper_id` 和 `item_id`，不能依赖 Markdown 行号或暴露本地文件路径。
- PDF 始终只读。条目解析、确认、编辑和删除纸面记录均不复制、移动、修改或删除用户的源 PDF。
